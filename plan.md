## Event profile (design, not built)

One **event file** describing a whole event, from which every device's profile is derived, so channel indexes and secrets cannot drift between radios, gateways and the apps. Decided 2026-10-10.

**Context.** Every aid station is self-contained: it runs its own full stack (bib logger, sweep tracker, a MeshCore gateway) and nothing is collected centrally. Winlink and voice through the team's own ham repeaters are the reliable data path; MeshCore is supplemental and region-wide MeshCore (repeaters between stations) is years away. So cross-station MeshCore data flows and MeshCore repeater/region work are out of scope for now.

**Channel plan.** Fixed indexes on every station radio, so app settings are identical at every station (sweep-tracker listens on 0, bib-logger on 1):

| Index | Channel | Secret | Scope (optional, later) |
|---|---|---|---|
| 0 | Sweeps | one for the event | event-wide |
| 1 | Aid station logging | per station | that station |
| 2 | Aid station chat (the crew) | per station | that station |
| 3 | All-race chat | one for the event | event-wide |

For 7 stations that is 16 channels in all (1 + 7 + 7 + 1). A station radio and its gateway hold only that station's four; a net-control device could hold all 16 (the Ethernet RAK build has 40 slots; some boards have 8).

**Rules.**
- Secrets are random 16-byte keys generated by the tool, never name-derived (guessable, so no isolation).
- Apply channels in index order and read them back to verify.
- The event file holds every secret and is sensitive (same rules as profiles: never committed or uploaded, gitignored). Per-station exports contain only that station's channels.
- Sweeps are the same in every export; trackers get only channel 0 (and the tracker name that becomes the team name in sweep-tracker).
- All-race chat floods everyone, so keep it low volume.

**Derived output.** Per station: companion profile(s); a gateway profile; and the go-box settings (`MESHCORE_ADDRESS`, channel indexes, which are constants). Plus tracker profiles and an optional all-channels profile.

**New device kind: gateway.** RAK4631 with the RAK13800 Ethernet module, firmware env `RAK_4631_companion_radio_ethernet` (exists in the fork: TCP port 5000, DHCP by default so reserve an address by its MAC on the AREDN node, 40 channel slots, PoE-capable). It is not in the fork's publish workflow yet. The meshcore-mqtt bridge on the station's go-box connects to it over TCP.

**Scope (deferred).** The companion firmware keeps one default flood scope per device (`TODO: have per-channel send_scope` in the fork); the phone app (v1.47+) sets a per-channel `region_scope` when sending. Keep `scope` as an optional field per channel. Do not build per-channel firmware scope or repeater region profiles until MeshCore repeaters exist; then a standalone radio that must send both narrow (station) and wide (all-race) traffic needs that firmware change.

**Open questions.** Which gateways can actually hear the sweep trackers (no repeaters: direct range only, so antenna placement). Whether the bridge needs per-channel handling beyond filtering on `channel_idx`.

**Build order.** (1) hardware-verify the existing flashing flows (item 1 above); (2) event file schema, key generation and per-station/tracker/gateway derivation as pure domain code with tests; (3) gateway device kind and adding its env to the publish workflow; (4) the go-box side (constant channel settings, docs) in `aredn-go-box`.

## Decisions

- Firmware is served by the same Go server as the app (same origin, no CORS) from a directory. The fork pushes an orphan `firmware` branch (`manifest.json` + newest 5 versions); clone it into `./firmware` to bake into the image or mount.
- A small Go server rather than static hosting: security headers, healthcheck, startup firmware verification, one container. No state, no database.
- Backups are opt-in per node, always passphrase-encrypted (PBKDF2-SHA256 600k + AES-GCM), delivered by download plus a prefilled `mailto:` (browsers cannot attach files).
- Trackers have no wipe or backup; flash + provision is the clean state.
